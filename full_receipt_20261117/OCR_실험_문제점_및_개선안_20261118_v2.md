# OCR 실험 검토: 확인된 문제와 다음 개선 실험

작성일: 2026-11-18 · 대상: KORIE 2차 학습 및 스마트폰 영수증 OCR

## 1. 검토 결론과 범위

**현재 2차 인식기를 유지하면서, 평가의 완전성과 검출 후 crop 품질을 먼저 개선하는 순서가 타당하다.** 비교 기준은 조각 병합을 끈 mobile 조정 설정으로 두고, server 검출기는 대안으로 유지한다. 이는 다음 실험의 기준점 제안이며 배포 성능이나 최적 설정의 확정은 아니다.

요청한 `OCR_실험측정_통합정리_20261118_v1.md`는 검토 중 `test_retro/` 아래 같은 이름의 문서에서 읽었다. 해당 문서, 기존 개선안 두 편, 저장된 평가 JSON, 학습 설정, 매칭 코드를 대조했다. 이 작업에서는 기존 문서를 수정하거나 이동·삭제하지 않았다. 다만 작성 후 링크 검사 시 `test_retro/` 폴더와 해당 문서들이 더 이상 확인되지 않아, 아래에는 읽었던 경로를 기록하고 현재 존재하는 실험 증거 파일만 링크했다. 경로 변경 원인은 확인하지 않았다.

이번 작업은 **문서·저장 결과 검토**다. 새 학습·추론, CER 상위 이미지 재선별·시각 검수, 새 bootstrap 실험은 하지 않았다. 아래에서 ‘확인’은 기존 측정 또는 코드로 확인한 내용이며, ‘제안’은 아직 수행하지 않은 작업이다. 기존 개선안의 임시 재집계는 이번에 독립 재현하지 않았다.

## 2. 의사결정에 필요한 확인 결과

모든 CER·EM은 별도 표시가 없으면 NFC 정규화와 공백·구두점 보존 기준이다. 차이는 퍼센트포인트(%p)다.

## 3. 문제점과 개선 방향

### P0. 부분 GT로는 전체 영수증 품질을 확정할 수 없다

**확인:** 현재 스마트폰 평가는 304장의 검증된 8,343줄에 대한 부분 GT 평가다. [매칭 코드](partial_matching_v1.py)는 IoU ≥ 0.5에서 최대 개수의 1:1 대응을 찾고, 같은 대응 수에서는 IoU 합을 우선한다. 미매칭 GT는 빈 문자열로 채점하고 미매칭 예측은 채점하지 않는다.

mobile 기본의 미채점 예측은 7,014개, mobile 조정은 8,394개다. 증가한 예측이 실제 미라벨 글자인지 오검출인지는 이 평가만으로 알 수 없다. 현재 CER을 ‘영수증 전체 CER’로 부르거나 precision으로 환산하면 안 된다. 반대로 미채점 예측을 전부 오검출로 처리해서도 안 된다. 검출 수 증가가 점수를 반드시 개선하는 것도 아니다. 박스 대응이 바뀌거나 인식이 악화될 수 있다.

**개선:** 현재 주 지표는 그대로 보존하고, 대표 조건을 포함한 소규모 영수증 집합에 모든 판독 가능한 글자와 ignore 영역을 명시한다. 그 집합에서 검출 precision/recall, 불필요한 출력, 누락, 읽기 순서까지 별도로 평가한다. 이미 진단한 자료에 완전 라벨을 추가하면 오류 분석에는 유용하지만 독립 test가 되지는 않는다. 제외된 1,732줄을 검수하는 것만으로 이미지 전체가 완전 GT가 된다고 가정하지 않는다.

### P0. 304장은 다음 개선의 최종 검증 세트가 될 수 없다

**확인:** 개발 48장과 나머지 256장 모두 이미 결과 진단에 노출됐다. 병합 포함 개선의 CER 감소는 개발 집합 약 2.52%p, 나머지 집합 약 0.61%p로 차이가 있다. 이는 선택한 개발 조건에 결과가 민감할 가능성을 보여주지만 과적합의 단독 증거는 아니다.

**개선:** 기존 304장은 개발·진단 자산으로 명시한다. 다음 학습에서는 동일 원본 영수증의 재촬영·유사 이미지가 split을 넘지 않도록 영수증 단위로 묶는다. 신규 미관측 영수증은 기기·촬영 거리·흐림·반사·긴 영수증·매장 양식을 고려해 확보하고, 설정과 모델 선택 후 한 번만 최종 평가한다. 특정 장수만으로 일반화가 보장된다고 쓰지 않는다. 필요한 수는 예상 효과와 영수증 간 변동을 보고 결정한다.

### P1. 검출·crop·인식 오류가 한 점수에 섞여 있다

**확인:** GT crop CER 8.18%와 초기 부분 OCR CER 21.45%의 차이는 입력 영역 및 매칭을 포함한 파이프라인 차이다. 이를 전부 검출기의 인과적 손실로 해석할 수 없다. 기존 미매칭 1,110줄의 과대 박스 494·분할 335·부분 겹침 137·겹침 없음 144 분류는 기하학적 진단이며, 모든 줄의 실제 원인을 수동 확정한 결과는 아니다.

**개선:** 동일 GT 집합과 동일 GT 문자 수를 분모로 고정하고, 전체 편집 오류를 ‘미매칭 GT에서 발생한 삭제’와 ‘매칭된 GT의 편집 오류’로 분해한다. matched-only CER은 별도 분모를 명시한다. GT crop도 같은 부분집합에서 비교해야 위치 오차의 영향을 더 명확히 볼 수 있다.

박스 여백·분할·병합을 한 번에 적용하지 말고 각각 실험한다. 여백은 기울어진 사각형의 글줄 방향을 따라 조정하고 인접 행 침범을 제한한다. 세로형 박스 또는 높이 임계값만으로 다중 행을 확정하지 않는다. 작은 박스를 제거하면 한 자리 수량·금액 기호가 사라질 수 있으므로 보존 지표를 둔다.

GT 영역 안의 예측들을 이어 붙이는 다대일 평가는 **정답 위치를 이용한 진단용 보조 점수**로만 사용한다. 실제 서비스에서는 GT 없이 행·열 및 읽기 순서를 판단해야 하므로 그 점수를 배포 성능으로 보고하지 않는다.

### P1. 조각 병합은 평균 이득이 작고 회귀가 있다

**확인:** 병합 추가는 편집 오류 17,350 → 17,303개, EM 약 −0.096%p, 미매칭 +1줄이다. 기본 설정 대비 개선된 전체 파이프라인에서 발생한 신규 미매칭 227줄을 모두 병합 탓으로 돌릴 수 없다. 해당 비교에는 검출 설정 변경도 포함된다.

**개선:** 병합은 기본 비활성으로 두고, 동일 검출 캐시에서 병합 전후의 정답→오답·오답→정답·대응 변경을 별도로 기록한다. 숫자 열, 수량 한 자리, 인접 행이 붙는 사례를 회귀 방지 대상으로 포함한다. 순증 미매칭 1줄만으로 총 회귀가 1줄이라고 해석하지 않는다. 병합 자체의 지연시간도 아직 별도 측정이 필요하다.

### P1. KORIE 보류 표본 문제를 스마트폰 전체에 그대로 적용하면 안 된다

**확인:** KORIE val 보류 92개는 전체 편집 오류의 약 56.7%를 차지한다. 외부 평가는 이 표본을 포함하며 학습 내부 평가는 사용 가능한 표본을 이용하므로 두 점수의 평가 모집단이 다르다. 보류에는 길이·사전 등의 조건이 있으므로 이를 모두 길이 초과 오류라고 부르지 않는다. 스마트폰 25자 초과 표본 CER 약 9.19%는 전체 8.18%와 차이가 있지만 KORIE 보류 집합과 같은 현상이라고 단정할 수 없다.

**개선:** 기존 공식 전체 점수를 유지하면서 보류 사유·길이·종횡비별 보조 표를 제공한다. 종횡비는 진단용 속성이지 다중 행 정답 판정이 아니다. 세로형 crop을 일괄 삭제하거나, 줄 수와 GT 토큰 수가 같다는 이유로 정답을 자동 배정하지 않는다. 다중 행 처리 실험에는 실제 대응이 확인된 라벨을 사용한다.

`max_text_length=25`, 학습 폭 320 및 다중 높이는 [train.yml](round2/run_001/train.yml)에 확인된다. 하지만 이것만으로 외부 추론의 모든 입력 폭도 320으로 고정된다고 결론낼 수 없다. 길이 상향과 폭 확대는 별도 변수로 시험하고 CTC/NRTR 인코딩, 위치 길이 제한, export 전처리, 기존 체크포인트 로딩을 함께 검사해야 한다.

### P2. 학습 불안정의 원인이 아직 확정되지 않았다

**확인:** 30 epoch 중 내부 val 최고 checkpoint는 epoch 5다. 이것만으로 학습이 거의 되지 않았거나 5 epoch에서 수렴했다고 단정할 수 없다. 증강·배치 구성의 영향을 받는 train loss와 내부 val, 전체 외부 val은 같은 척도가 아니다.

**개선 순서:** 같은 checkpoint와 고정 입력의 반복 평가 → 증강 없는 고정 train 부분집합 진단 → 초기 checkpoint와 학습 checkpoint 비교 → 증강 및 BN 처리의 개별 대조 실험 순으로 진행한다. BN 원인은 현재 가설이다. train mode 순전파를 이용한 BN 통계 재보정은 optimizer를 쓰지 않아도 모델 버퍼를 변경하므로 ‘추론만’으로 분류하지 않는다. 복제 모델과 train 자료만 사용하고, 변경 전후 해시와 외부 val 결과를 기록한다.

학습률·epoch·증강을 동시에 바꾸지 않는다. 내부 acc로 선택하는 현재 규칙과 외부 전체 val CER의 차이를 확인하고, 다음 실험의 선택 규칙을 실행 전에 고정한다. 과거 test 결과를 보고 checkpoint를 다시 선택하지 않는다.

### P2. 공백·사전 처리는 평가 정책과 모델 개선을 구분해야 한다

**확인:** GT crop의 공백 무시 EM 70.61%는 공백 보존 EM 59.49%와 다른 채점 규칙이다. 같은 예측을 재채점한 것이므로 ‘후처리로 정확도를 즉시 11%p 개선했다’는 의미가 아니다. 공백 제거 후에는 CER 분모도 달라진다.

[최종 문자 감사](text_rules_audit_20261118_v1/verified_audit.json)는 실제 runtime의 사전 순서 일치와 CTC 반복·blank·space 처리를 확인했다. 중간 비교의 `ordered_match_export_vs_train:false`만 읽고 사전 불일치 버그로 판정하면 안 된다. NFC로 바뀐 GT·예측이 없어 현재 결과를 한글 정규화 오류로 설명할 근거도 없다. OOV는 85줄로 실제 한계이지만 전체 문제를 설명하지는 않는다.

**개선:** 원문 OCR 결과를 보존하고 필드 파싱 결과를 별도 저장한다. 금액·전화번호·날짜 등 확인된 필드에서만 형식 규칙을 적용하고, 숫자·기호 문자열 EM과 금액 필드 EM을 분리한다. `8.000 → 8,000`, `O → 0` 등을 문맥 확인 없이 일괄 치환하지 않는다. 산술 불일치는 자동 정답 교정보다 검토 신호로 사용한다. 사전 확장은 충분한 train 예제와 기존 문자 인덱스·헤드 가중치 이식 검증을 갖춘 별도 실험으로 둔다.

### P2. 현재 속도는 휴대폰·실서비스 응답시간이 아니다

**확인:** RTX 5070 Ti에서 mobile/server 조정 검출 평균은 20.8/70.4ms, 전체 OCR 평균은 0.405/0.448초다. 검출 시간은 약 3.4배 차이지만 전체 OCR 차이는 약 43ms, 10.7%다. 전체 p95는 0.896/0.925초다. GPU 순차 실행 측정이며 네트워크·큐·초기화 등이 제외됐다.

**개선:** 검출 단계 배수만으로 server를 배제하거나, 현재 구성을 처리량 최적이라고 선언하지 않는다. mobile의 crop 인식 평균 약 0.274초도 있으므로 인식 배치·crop 수와 전체 비용을 함께 본다. 서버 동시 요청·VRAM·cold start·업로드 시간을 별도로 측정한다. 스마트폰 스캐너 도입은 원근 보정 전후의 동일 영수증 paired 평가로 검증하고, 촬영 품질 안내와 OCR 성능을 별도 측정한다.

## 4. 기존 개선안에서 수정해야 할 해석

| 기존 제안 또는 해석 | 이번 검토의 수정 의견 |
|---|---|
| 세로형 crop 오류가 크므로 원인은 다중 행이다 | 종횡비 집계는 상관관계다. 실제 행 구성·정답 대응을 확인하기 전에는 가설로 둔다. |
| 길이 25→60, 폭 320→640+, 패딩 10~15%를 바로 적용 | 검증되지 않은 후보값이다. 변수별 실험과 라벨 보존 검사가 먼저다. |
| BN 재보정은 추론만으로 가능한 원인 확인 | 모델 통계가 변경되는 실험이다. 독립 복제·train-only 보정과 대조군이 필요하다. |
| 신규 미매칭 227개는 병합의 문제 | 검출 설정+병합의 합성 변경 결과다. 병합 단독 비교로 원인을 분리한다. |
| 공백 제거·기호 치환으로 즉시 정확도 개선 | 재채점, 실제 예측 변경, 구조화 필드 정확도를 따로 보고한다. |
| 일부 라벨 추가 또는 50~100장 확보로 일반화 보증 | 완전성·독립성·표본 구성과 불확실성을 확인해야 하며 장수만으로 보증되지 않는다. |
| 작은 박스 제거로 속도 개선 | 한 자리 수량·기호 누락 위험을 먼저 측정한다. |
| 기존 개선안의 재집계 수치를 재현 가능한 확정 근거로 사용 | 임시 실행 스크립트·결과가 보존되지 않은 집계는 재현 코드를 함께 남겨야 한다. 이번 문서는 독립 재현을 주장하지 않는다. |

초기 검출기 비교에서 설정 인자가 누락됐던 이력은 [정정 기록](detector_comparison_20261118_v1/default_settings_evidence/protocol_correction.json)에 남아 있다. 최종 조정 비교는 설정을 명시하고 mobile 재실행의 차이 없음도 확인했다. 초기 기본값 결과와 최종 조정 결과를 섞지 않되, 정정 이력만으로 최종 비교 전체가 무효라고 볼 이유도 없다.

## 5. 다음 실행 계획과 통과 기준

아래는 후속 작업의 설계이며 이번 문서 작성에서 실행한 항목은 아니다.

| 순서 | 실행할 작업 | 고정·변경 변수 | 완료 및 채택 판단 |
|---|---|---|---|
| 1 · 기록 고정 | 모델·데이터·유효 runtime 설정·코드 해시를 하나의 manifest로 묶고 원문 예측·검출 캐시를 연결 | 현재 2차 rec, mobile 조정, 병합 없음 기준 | 동일 입력의 예측과 기존 집계 재현. 경로 변경에도 상대 경로와 해시로 추적 가능 |
| 2 · 평가 보완 | 완전 GT/ignore 소집합, 필드 GT, 신규 독립 test 설계 | 기존 부분 GT 지표는 보존 | 부분·완전 GT 지표를 구분하고 숫자/금액/수량 평가 정의 고정 |
| 3 · 영역 처리 | 여백만 → 조건부 분할만 → 조건부 병합만 비교 | 인식기·검출 가중치·채점 고정 | 동일 영수증 paired 차이, 회귀 줄, 미채점 예측 수, 지연시간 기록 |
| 4 · 인식 학습 진단 | 고정 입력 평가, 증강 및 BN 대조; 확인된 단일 행 crop으로 후속 학습 | 한 실험에 한 주요 변수, 공식 split 유지 | 누락 파라미터 없는 로딩·smoke·export 재평가 통과, val 선택 규칙 준수 |
| 5 · 확장 후보 | 길이/폭, OOV 사전, 타일링·보정 등 필요성이 확인된 후보만 시험 | 각각 독립 run | 개선 근거와 자원 증가를 비교하고 기존 정답의 회귀 점검 |
| 6 · 최종 검증 | 선택 모델·전처리·필드 규칙 동결 후 신규 test 및 서비스 지연 측정 | test를 본 뒤 재선택하지 않음 | 성능 차이와 불확실성, 금액·수량 오류, p95·메모리·실패율 보고 |

**채택 원칙:** 주 지표는 공백 보존 CER, 보조 지표는 문자열 EM·숫자/기호 EM·확인된 금액/수량 필드 정확도다. 지표가 엇갈리면 단순히 CER 최저값만 선택하지 않는다. 허용할 필드 회귀와 서비스 지연 예산은 후보 결과를 보기 전에 정한다. 영수증 단위 paired 불확실성도 함께 보고하며, 차이가 불명확하면 운영 전환을 보류하고 현재 기준을 유지한다. 완전 GT가 없으면 precision 개선을 주장하지 않는다.

후속 코드에는 `experiment_manifest.json`, 줄별 전후 예측과 매칭 근거, 지표의 분자·분모, 단계별 시간, 실패 목록을 출력하게 한다. 평가의 빈 예측·다중 후보·동일 IoU·분할/병합 대응, 변경된 모델/데이터의 재개 거부를 검증한다. 기존 성공 결과를 덮어쓰지 않고 새 run 폴더를 사용한다.

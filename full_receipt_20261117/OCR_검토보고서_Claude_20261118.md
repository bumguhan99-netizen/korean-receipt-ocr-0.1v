# OCR 검토 보고서: 문제점과 개선안 (Claude 작성)

작성일: 2026-11-18 · 검토 대상: `OCR_실험측정_통합정리_20261118_v1.md`와 이 문서가 연결한 결과 파일

이번 검토에서는 학습과 추론을 새로 실행하지 않았다. 저장된 예측 CSV, 학습 로그, 비교 JSON만 다시 집계했다. 새로 계산한 수치에는 **[재집계]** 표시를 붙였다.

## 0 요약

1. **KORIE crop 오류의 절반 이상은 여러 줄이 들어 있는 세로형 crop에서 나온다.** 통합정리 문서는 이 오류를 "길이 때문에 보류된 어려운 표본"으로 설명했다. 실제 원인은 길이가 아니라 crop 형태다. 단일 줄 인식기로는 이 구조를 해결할 수 없다.
2. **2차 학습의 내부 검증 정확도가 0.37~0.79 사이에서 크게 흔들렸다.** 학습 loss도 30 epoch 동안 거의 줄지 않았다. epoch 5의 best는 이 흔들림의 최고점이라서 checkpoint 선택이 우연에 좌우될 수 있다.
3. 1차→2차 개선 폭(test CER −0.47%p)은 작지만 영수증 단위 bootstrap 범위가 0을 포함하지 않는다. 개선은 주로 5자 이하 짧은 문자열에서 나왔다.
4. **스마트폰 평가는 정답이 없는 검출을 채점하지 않는다.** 그래서 검출 박스를 늘리는 설정 변경은 불이익 없이 점수만 오를 수 있다. 조정 설정에서 채점되지 않은 검출이 19.7% 늘었다.
5. 스마트폰 304장은 모두 진단과 설정 선택에 노출되었다. 따라서 아직 미관측 최종 test가 없다.
6. 스마트폰 전체 OCR CER 20.58% 중 10.58%p는 정답 줄과 매칭되지 않은 줄에서 나온다. 매칭된 줄만 보면 CER은 11.18%다. 가장 먼저 개선할 단계는 인식이 아니라 검출과 영역 분할이다.

## 1 KORIE: 여러 줄 crop이 오류의 주원인

### 확인 내용

`round2/run_001/{validation,final_test}/candidate_predictions.csv`와 `data/ocr` 이미지 크기를 결합해 다시 집계했다. **[재집계]**

| 분할 | 가로/세로 비 < 1 crop 수 | 전체 대비 | 오류 문자 점유율 | 해당 crop CER | 나머지 CER | 나머지 문자열 정확도 |
|---|---:|---:|---:|---:|---:|---:|
| validation | 268 | 15.0% | 54.8% | 74.5% | 12.75% | 82.4% |
| test | 285 | 16.0% | 56.1% | 71.9% | 10.85% | 81.2% |

- 필드별 crop 가로/세로 비 중앙값: `Item_Quantity_Item_Weight` 0.33, `Item_Unit_Price` 0.77. 두 필드는 품목 여러 개의 수량·단가를 한 열로 묶은 crop이다.
- 예: `val/IMG00038_Item_Unit_Price.jpg`의 정답은 `1,500 1,500 1,500 1,000`이고 예측은 `1000`이다. `val/IMG00047_Item_Unit_Price.jpg`에는 가격 6개와 함께 정답에 없는 품목명 조각(`00g/1봉`, `2송이` 등)도 들어 있다.
- 25자를 초과하는 val crop 79개의 정답 평균 길이는 36.8자인데 2차 예측의 평균 길이는 10.8자다. 모델이 여러 줄 중 일부만 읽고 있다는 뜻이다.
- **학습 데이터에도 섞여 있다.** 25자 이하라서 보류되지 않은 train 5,087개 중 713개(14.0%)가 세로형 crop이다. 단일 줄 인식기에 여러 줄 이미지와 공백으로 이은 정답을 학습시키는 셈이다. 이는 아래 2절의 학습 불안정과도 관련이 있을 수 있다(미검증 가설).

### 통합정리 문서의 문제

- "길이 때문에 보류된 92개, CER 75.34%"라는 설명은 수치는 맞지만 원인 해석이 부정확하다. 보류 표본은 대부분 여러 줄 crop이다. 보류되지 않은 세로형 crop도 많다.
- 논문 수치(정답 박스 CER 11.72%)와 비교할 때 이 구조 차이를 빼면 오해가 생긴다. 세로형 crop을 제외한 나머지 CER(val 12.75%, test 10.85%)은 논문 수치와 비슷한 범위다. 다만 데이터 규모가 달라(8,927 vs 17,587) 동일 비교는 아니다.

### 개선안

| 순서 | 내용 | 검증 방법 |
|---|---|---|
| 1 | 모든 KORIE 보고에 **단일 줄 / 여러 줄 crop 하위 집계**를 추가한다. 기준(가로/세로 비, 또는 crop 안 검출 줄 수)은 val에서 고정한다. | 기존 예측 CSV만으로 바로 계산 가능 |
| 2 | 추론: crop 안에서 텍스트 검출을 한 번 더 돌린다. 줄을 위→아래로 정렬해 각각 인식한 뒤 공백으로 잇는다. 검출이 실패하면 기존 단일 인식으로 되돌아간다. | val에서 여러 줄 집합 CER과 단일 줄 집합 비악화 여부 확인 |
| 3 | 학습: 세로형 crop은 (a) 학습에서 제외하거나, (b) 2번의 줄 분할 결과에서 줄 수와 정답 토큰 수가 정확히 같을 때만 줄 단위 표본으로 변환한다. 일치하지 않는 표본은 사유를 기록하고 제외한다. 원본은 수정하지 않는다. | 제외·변환 수 기록. 3차 실험으로 별도 run 생성 |
| 4 | 정답에 없는 품목명 조각이 crop에 들어간 경우는 데이터 특성이다. 이 부분은 인식기 학습으로 해결할 대상이 아니며, 보고서에 한계로 명시한다. | — |

## 2 2차 학습 과정의 불안정

### 확인 내용 (`round2/run_001/outputs_train/train.log`, `train.yml`)

- `eval_batch_step: [0, 100]`이므로 100 step(약 0.45 epoch)마다 내부 검증을 실행했다. 66회 평가의 acc 범위는 **0.370~0.790**이다. 연속된 두 평가 사이에서도 0.79→0.58→0.78처럼 크게 변했다.
- 첫 평가(step 100, lr ≤ 4e-6)의 acc는 0.473이다. 1차 모델을 같은 1,693개 표본에 외부 평가하면 문자열 정확도가 75.25%다. **[재집계]** 학습률이 매우 낮은 구간에서 정확도가 이만큼 떨어지는 것은 가중치 변화만으로는 설명하기 어렵다.
- 학습 loss: 시작 6.81, epoch 30 끝 7.02~7.75. train acc도 0.62~0.72 사이를 계속 맴돌았다. 30 epoch 동안 학습이 거의 진행되지 않았다.
- best는 epoch 5(acc 0.7897)다. 이후 25 epoch는 선택에 기여하지 않았다.

### 원인 가설 (미검증)

1. **BatchNorm 이동 통계의 변동.** 학습 입력은 높이 32/48/64 멀티스케일이고 RecConAug(확률 0.5)로 이어붙인 이미지다. 반면 평가 입력은 3×48×320 고정이다. BN 이동 평균은 최근 배치에 크게 좌우된다. 그래서 평가 직전에 어떤 배치가 들어왔는지에 따라 정확도가 흔들릴 수 있다.
2. 1절의 여러 줄 crop(train 14%)이 노이즈 라벨로 작용해 loss가 줄지 않는다.

### 개선안

| 순서 | 내용 |
|---|---|
| 1 | 가설 1 검증: 같은 checkpoint를 (a) 그대로 평가하고, (b) 높이 48 train 배치 몇 개를 train 모드로 forward만 해서 BN 통계를 갱신한 뒤 평가한다. 두 결과 차이가 크면 BN이 원인이다. 추론만 필요하고 학습은 필요 없다. |
| 2 | 원인이 BN이면 미세조정 중 BN을 고정한다(eval 모드 유지 또는 momentum 상향). 아니면 단일 스케일(48)로 학습해 비교한다. |
| 3 | checkpoint 선택을 내부 acc 단일 최고점에서 바꾼다. 매 epoch 끝에 외부 val CER을 함께 기록하고, 최근 몇 개 checkpoint의 평균이나 EMA를 후보에 넣는다. 선택 규칙은 학습 전에 고정한다. |
| 4 | LR 1e-5에서 loss가 거의 줄지 않았으므로, 1절 데이터 정리 후 소수의 LR 후보(예: 1e-5, 3e-5, 1e-4)를 val로만 비교한다. 후보값은 최적값이 아니라 탐색 범위다. |
| 5 | 3차 실험은 기존 `round2/run_001`을 덮어쓰지 않고 새 run으로 만든다. test는 checkpoint를 고정한 뒤 한 번만 실행한다. |

## 3 1차→2차 비교 보강

### 확인 내용 [재집계]

| 항목 | validation | test |
|---|---:|---:|
| CER 차이 (2차−1차) | −0.61%p | −0.47%p |
| 영수증 단위 paired bootstrap 95% 범위 (2,000회, seed 0) | −0.79 ~ −0.42 | −0.70 ~ −0.25 |
| 5자 이하 CER | 6.41 → 4.77 | 6.26 → 4.68 |
| 5자 이하 문자열 정확도 | 85.9 → 89.3 | 84.7 → 89.3 |
| 25자 초과 CER | 76.24 → 76.31 | 76.60 → 77.27 |
| 숫자·기호 문자열 정확도 | 75.63 → 78.16 | 74.78 → 76.83 |
| 금액 필드 문자열 정확도 | 76.32 → 78.14 | 77.22 → 77.58 |

- 개선은 통계적으로 일관되지만 폭이 작고, 주로 짧은 문자열과 `Item_Quantity_Item_Weight`에서 나왔다. 여러 줄·긴 crop은 개선되지 않았고 test에서는 조금 나빠졌다.
- 금액 필드 test 개선은 562개 중 2개 차이(+0.36%p)다. 금액 정확도가 개선됐다고 주장하기에는 부족하다.
- test bootstrap은 보고용으로만 썼고 모델 선택에는 사용하지 않았다.

### 통합정리 문서의 문제와 개선안

- 통합표에 숫자·기호 문자열 정확도와 금액 필드 정확도가 빠져 있다. 평가 계획은 두 지표를 분리 보고하도록 요구했고 값도 이미 `summary.json`에 있다. → 통합표에 열을 추가한다.
- KORIE 1차→2차 비교에는 신뢰구간이 없고, 검출기 비교에만 bootstrap이 있다. → 같은 방식으로 모든 모델 간 비교에 넣는다.

## 4 스마트폰 평가 방식의 편향

### 확인 내용 [재집계 포함]

| 조건 | 총 검출 | 채점되지 않은 검출 | 미매칭 정답 | CER |
|---|---:|---:|---:|---:|
| mobile 기본 | 14,247 | 7,014 | 1,110 | 21.45% |
| mobile 조정 | 15,754 (+10.6%) | 8,394 (+19.7%) | 983 | 20.58% |
| server 기본 | 14,592 | 7,277 | 1,028 | 20.67% |
| server 조정 | 15,460 | 7,985 | 868 | 20.36% |

- 정답이 붙지 않은 검출은 채점하지 않는다(부분 GT라서 의도된 설계다). 그 결과 `box_thresh`를 낮추고 입력 해상도를 높이는 변경은 오검출이 늘어도 감점되지 않는다. 늘어난 1,380개가 실제 미라벨 글자인지 오검출인지는 아직 모른다.
- 미매칭 줄의 기여 **[재집계]**: mobile 조정 CER 20.58% 중 10.58%p(오류의 51.4%)가 미매칭 정답에서 나온다. 매칭된 줄만 보면 CER은 11.18%로, 정답 crop CER 8.18%와 약 3%p 차이다.
- 1:1 IoU ≥ 0.5 매칭은 박스 분할(335줄)이나 과대 박스(494줄)를 모두 "미매칭"으로 처리한다. 그래서 검출 누락과 박스 경계 문제가 한 수치에 섞인다.
- 설정 선택에 쓴 48장과 나머지 256장이 모두 진단에 노출되었다. 나머지 256장의 개선 폭은 21.66→21.05%(−0.61%p)로, 개발 표본의 개선 폭(−2.52%p)보다 훨씬 작다.

### 개선안

| 순서 | 내용 |
|---|---|
| 1 | 모든 검출 비교표에 **장당 검출 수와 채점되지 않은 검출 수**를 함께 싣는다. 검출 수가 늘어난 설정의 개선은 별도 경고를 붙인다. |
| 2 | 20~30장 정도의 소규모 하위 집합에 **완전 라벨 또는 ignore 영역**을 만든다. 그 집합에서 precision/recall을 측정한다. 이 집합은 검출기 학습에도 필요하다(통합정리 7절과 같은 결론). |
| 3 | 1:1 매칭과 함께 **다대일 매칭**(정답 영역 안에 중심이 들어간 예측 박스를 읽기 순서대로 이어 붙여 채점)을 보조 지표로 추가한다. 분할 오류와 인식 오류를 분리할 수 있다. 규칙은 개발 표본에서 고정한다. |
| 4 | **새 스마트폰 영수증으로 미관측 test 세트를 확보한다.** 현재 304장으로 정한 정책(검출 설정, 조각 연결 여부, mobile/server)을 동결한 뒤 한 번만 평가한다. |
| 5 | 조각 연결은 CER −0.06%p, 문자열 정확도 −0.10%p로 효과가 거의 없고 지표 간 방향도 엇갈린다. 운영 정책에서는 끄는 것을 기본으로 하고, 4번 test에서 다시 판단한다. |

## 5 공백·사전·정규화

- 정답 crop에서 공백만 다른 오답이 928줄(11.1%)이다. CER 8.18%와 문자열 정확도 59.49%의 큰 차이의 상당 부분이 여기서 나온다.
- 예시 crop(`1, 280`, `2, 980`)처럼 인쇄 자체에 쉼표 뒤 간격이 있는 경우가 있다. 라벨 규칙이 이를 어떻게 처리했는지 확인이 필요하다.

### 개선안

- **필드 성격별 공백 정책**을 정한다. 금액·전화번호·날짜는 서비스에서 공백을 제거하고 파싱한다(예: 숫자 그룹 사이 공백 제거). 상호·주소는 공백 보존을 유지한다. 주 지표(공백 보존)는 그대로 두고, 서비스 지표를 따로 보고한다.
- 사전 밖 문자(85줄, 약 1%)는 우선순위가 낮다. 사전을 바꾸면 출력 헤드가 바뀌므로 첫 개선 대상으로 삼지 않는다. `₩` 같은 기호는 후처리 정책 수준에서 먼저 검토한다.

## 6 속도 해석

- mobile 조정 전체 OCR 0.405초/장 중 crop 인식이 0.274초(68%), 검출은 0.021초(5%)다(`comparison.json`).
- server 검출기는 검출만 보면 3.4배 느리지만 전체 시간 증가는 +0.043초(+11%)다. 정확도 차이는 신뢰구간이 0을 포함한다.
- 개선안: 속도 최적화는 인식 단계(배치 크기, 아주 작은 박스 제거, 인식 대상 수 감소)에 집중한다. 검출기 선택은 4절의 미관측 test 결과로 정한다. 휴대폰 실측은 별도로 한다.

# OCR 개선 실험 실행 설계

작성일: 2026-11-18  
문서 구분: **후속 구현·평가·학습 계획서** — 문제점 분석 보고서와 구분  
반영 근거: [OCR 실험 문제점 및 개선안 v2](../OCR_실험_문제점_및_개선안_20261118_v2.md)

## 1. 목표와 실행 범위

스마트폰 영수증에서 검출 경계·분할·인식·필드 추출 오류를 구분하고, 확인된 원인에 대응하는 변경만 채택한다. KORIE 2차 인식기를 기준으로 영역 처리부터 검증한 뒤 필요한 인식 학습을 진행한다. 모델 크기 확대, 사전 변경, 긴 문자열 지원은 독립 실험으로 분리한다.

이 문서는 설계 산출물이다. 아래 새 모듈·명령 단계·폴더는 **구현 예정**이며, 존재하거나 실행 완료된 것으로 간주하지 않는다. 이번 작성에서는 모델·라벨·서비스 코드를 변경하거나 학습·추론을 실행하지 않는다.

실행 흐름은 `기록 고정 → 평가 재현 → 영역 처리 단일 변수 실험 → 필요 시 인식 학습 → 후보 동결 → 독립 검증`이다. 완전 GT·신규 test 확보는 병행하되, 준비 전에도 기존 자료의 재현·진단·코드 구현을 진행할 수 있다. 독립 자료가 없으면 결과 상태는 ‘개발 자료에서 개선’으로 한정한다.

## 2. 변경하지 않을 비교 기준

| 항목 | 고정 기준 |
|---|---|
| 인식기 | 기존 2차 선택 모델. 가중치 SHA256 `10e0e6b65bce1582339440abcf844e1c1e40a1d6357c5722a177c0dabce8a155`를 입력 검사에서 확인 |
| 기본 검출기 | `PP-OCRv5_mobile_det`; 인식기와 검출기 파일·설정 해시 모두 기록 |
| 유효 검출 설정 | `limit_side_len=1920`, `limit_type=max`, `thresh=0.3`, `box_thresh=0.45`, `unclip_ratio=1.2` |
| 영역 처리 기준 | 기존 회전 crop 방식, 추가 여백·분할·병합 없음. 기존 구현과 실제 설정을 manifest에 기록 |
| 스마트폰 주 지표 | 기존 검증 GT 8,343줄의 부분 OCR CER·EM, NFC만 적용, 공백·구두점 보존 |
| 매칭 | IoU ≥ 0.5, 최대 개수 1:1 대응 및 IoU 합 우선. 미매칭 GT는 빈 문자열, 미매칭 예측은 미채점 |
| KORIE | 공식 split 유지. 보류 표본을 포함한 외부 전체 val 결과와 학습 내부 val 결과를 구별 |
| 기존 test | 완료된 결과 보존. 후속 설정·checkpoint 선택에 사용하지 않음 |

기준 확인값은 스마트폰 부분 CER **20.57979266%**, EM **50.36557593%**, 미매칭 **983줄**, 편집 오류 **17,350개 / GT 84,306자**다. 이 수치는 [검출기 비교 결과](../detector_comparison_20261118_v1/comparison.json)의 mobile 조정·병합 없음 조건에 해당한다. 구형 기본 설정이나 병합 포함 결과와 섞지 않는다.

## 3. 데이터·라벨·평가 설계

### 3.1 데이터 역할

| 집합 | 용도 | 제한 |
|---|---|---|
| 기존 개발 48장 | 구현 smoke, 파라미터 후보 축소, 기하학 규칙 개발 | 이미 노출된 개발 자료 |
| 기존 나머지 256장 | 개발 집합 밖의 회귀와 조건별 편차 진단 | 기존 분석에 노출됐으므로 독립 test로 부르지 않음 |
| 기존 전체 304장 | 기준 재현, 최종 개발 비교, 기존 성능과 연속성 확보 | 전체 결과를 보고 설정을 고르면 일반화 주장 불가 |
| 완전 GT 개발 소집합 | 검출 precision/recall, 추가 출력, 읽기 순서 검증 | 기존 자료에서 만들면 계속 개발 자료임 |
| 신규 영수증 test | 정책 동결 후 일반화 확인 | 원본 영수증·재촬영 그룹이 train/dev와 겹치지 않아야 함 |
| KORIE train/val | 인식 학습 및 기존 도메인 회귀 검증 | 공식 test를 선택 과정에 재사용하지 않음 |

완전 GT 개발 소집합은 우선 24장을 작업량 추정용 시작 규모로 제안한다. 긴 영수증·기울기·반사/흐림·작은 숫자·다양한 매장 양식을 포함하도록 촬영 메타데이터와 문서 형태로 선정한다. 이 장수는 통계적 충분성을 의미하지 않는다. CER 상위 이미지의 신규 선별·검수는 본 계획의 자동 실행 단계에 포함하지 않는다.

완전 라벨은 모든 판독 가능한 글자에 polygon·텍스트·읽기 순서·필드 종류를 부여하고, 판독 불가 영역은 ignore 사유를 기록한다. 기존 제외 1,732줄의 복구만으로 완전성을 선언하지 않는다. 부분 라벨 자료를 검출 학습에 직접 넣어 미라벨 글자를 배경으로 처리하지 않는다.

신규 test 규모는 개발 자료의 영수증 단위 변동과 검출하려는 최소 차이를 이용해 사전에 결정한다. 표본 수 산정과 수집 완료까지 test 상태는 `pending`으로 둔다. 독립 test가 없는 상태에서 기존 304장을 다시 분할해 ‘미관측’이라고 표기하지 않는다.

### 3.2 평가 계층

| 계층 | 측정값 | 해석 |
|---|---|---|
| GT crop 인식 | 전체 CER·EM, 숫자/기호 EM, 길이·OOV별 보조 집계 | 정답 위치에서의 인식 성능 |
| 기존 부분 OCR | CER·EM, 미매칭 GT, 미채점 예측, 검출 수 | 과거 결과와 비교하는 주 지표. 전체 precision 아님 |
| 완전 GT 검출 | precision/recall/F1, 누락·추가 검출 | polygon 매칭·ignore 정책을 별도 버전으로 고정 |
| 구조화 필드 | 금액·수량·날짜 등 필드별 EM, 필드 누락·추가 출력 | 필드 정답이 있는 자료에서만 측정 |
| 서비스 | 전체 및 단계별 평균/p50/p95, 실패율, VRAM | GPU 로컬 시간과 업로드·큐 포함 응답시간 분리 |

부분 OCR의 오류 분해는 동일 GT 문자 수 `N`으로 `CER = (미매칭 GT 문자 수 + 매칭 GT 편집거리 합) / N`을 사용한다. matched-only CER은 별도 분모를 함께 표기한다. GT crop과 검출 crop 비교도 동일 GT 부분집합을 사용한다. 원문 CER과 공백 제거 재채점은 별도 열로 유지한다.

완전 GT 검출의 제안 규칙은 판독 가능 GT를 먼저 polygon IoU ≥ 0.5로 1:1 매칭한 뒤, 남은 예측 중 ignore 영역에 대한 교집합/예측 면적 ≥ 0.5인 항목을 채점에서 제외하는 방식이다. 나머지 예측은 FP, 미매칭 판독 가능 GT는 FN으로 집계한다. 작은 글자를 포함한 합성 사례로 검증한 후 개발 자료에서 규칙을 동결한다. 이 지표를 기존 축 정렬 부분 GT 점수와 직접 혼합하지 않는다.

금액은 통화·부호·소수점 규칙을 명시한 파서로 GT와 예측 모두에 동일 적용한다. 원문 필드 EM과 파싱된 값 EM을 분리한다. `O→0`, `8.000→8,000` 같은 추측 치환은 기본 비활성이다. 산술 불일치는 원문을 변경하지 않고 검토 신호로 저장한다.

## 4. 실험 목록과 단계별 통과 조건

후보 수를 줄이기 위해 단일 변수 결과를 먼저 보고 조합은 마지막에 수행한다. 아래 숫자 후보는 시작값이며 최적값으로 간주하지 않는다.

| ID | 목적·변경 변수 | 실행 방법 | 다음 단계 조건 |
|---|---|---|---|
| E00 | 저장 결과 및 환경 재현 | 캐시 재채점 후 기준 조건 소량 추론; 일치하면 전체 304장 확인 | 표본 ID·GT 분모·편집 수·매칭 수 일치. 추론 차이는 원인 기록 후 해소 |
| E01 | crop 좌우 여백 | 검출 캐시 고정, 글줄 방향 길이의 각 측면 0/2/5% 확장, 상하 0%, 이미지 경계 제한 | 인접 행 침범·숫자/수량 회귀와 CER·EM을 함께 평가 |
| E02 | 상하 여백 | E01에서 선택한 좌우 정책 고정 후 높이의 각 측면 0/2/5% | 추가 글줄 유입과 인식 개선의 균형 확인 |
| E03 | 조건부 분할 | 다중 행 후보를 영상 근거로 판별, 실제 줄 대응이 확인된 개발 예제로 규칙 작성 | GT를 입력으로 사용하지 않는 분할과 읽기 순서 확인; 자동 GT 토큰 배정 금지 |
| E04 | 조건부 병합 | 동일 검출 캐시에서 기존 병합 off/on 대조 후 필요한 조건만 제한 | 정답→오답·오답→정답·매칭 변경 및 병합 지연 별도 기록 |
| E05 | 인식 안정성 진단 | 고정 입력 반복 평가, 초기/학습 checkpoint 비교, 고정 train 부분집합의 증강 없는 진단 | 비결정성·설정 불일치부터 해결. BN 원인을 단정하지 않음 |
| E06 | BN 가설 | 모델 복제 후 train 자료만으로 통계 재보정; 원본과 대조 | 버퍼·가중치 해시 변화 및 val 결과 기록. val/test로 통계 갱신 금지 |
| E07 | 스마트폰 인식 미세조정 | 검증 crop과 원본 영수증 그룹 기반 train/dev 구성, 구조·사전 유지 | 데이터 누수 검사, smoke, 전체 dev 및 KORIE val 회귀 검증 |
| E08 | 길이 지원 | E07과 별도 run에서 max_text_length 25/40 비교 | 실제 길이별 누락, CTC/NRTR·체크포인트 호환 확인 |
| E09 | 입력 폭 지원 | 길이 정책 고정 후 학습 폭 320/480 비교 | 실제 외부 추론 resize 정책까지 기록. 지연·VRAM 증가 평가 |
| E10 | 확장 후보 | OOV 사전·타일링·보정·server 대안 중 근거 있는 항목만 독립 실험 | train 예제·구현 검사·개발 비교를 통과한 후보만 조합 |
| E11 | 최종 조합·동결 | 통과한 변경만 결합하고 재평가 | 결합 효과 재검증 후 정책·모델 해시 동결 |
| E12 | 독립 test·서비스 검증 | 신규 test 1회 평가, 운영 조건 성능 측정 | 결과 보고 후 종료. 같은 test를 보고 모델 재선택하지 않음 |

E03/E04는 단순 종횡비·높이만으로 자동 실행하지 않는다. 이미지 좌표·검출 ID·crop ID·분할/병합 부모 ID를 보존한다. GT 내부 조각을 합치는 방식은 별도의 oracle 진단으로만 두고 E03/E04의 서비스 성능에 포함하지 않는다.

### 4.1 후속 학습의 구체적 시작 설계

E07의 스마트폰 train/dev는 기존 304장 내 원본 영수증 그룹 기준으로 약 80/20, seed 42로 생성하되 정확한 그룹 수와 조건별 분포를 manifest에 남긴다. 이는 학습 선택용 개발 분할이며 독립 검증이 아니다. 원본 재촬영 그룹 정보가 없으면 이미지 해시·유사도 후보와 메타데이터로 중복 관계를 확인하고 미해결 그룹은 학습 입력에서 보류한다. 공식 KORIE split은 변경하지 않는다.

2차 학습용 `.pdparams`를 export 모델과 동일한 후보인지 검증한 후 사용한다. 추론 `.pdiparams` 이름 변경으로 대체하지 않는다. 새 실험 optimizer는 초기화하며 같은 run 재개에만 optimizer/states를 사용한다.

첫 후보는 seed 42, LR 1e-5, 최대 10 epoch, 시작 batch 16, 기존 증강·구조·사전 유지로 설계한다. 이는 스마트폰 추가 튜닝의 탐색 시작값이다. 64개 이하 train 표본·작은 배치·2 epoch smoke를 별도 run에서 통과시킨 뒤 본 학습은 원래 초기 가중치부터 시작한다. batch는 메모리에 맞춰 조정하되 실제 유효 batch와 변경 이유를 기록한다.

최초 E07은 스마트폰 train만으로 수행하고, KORIE val 회귀가 있으면 KORIE train을 섞는 별도 비교를 설계한다. 여러 요인을 동시에 바꾸지 않는다. checkpoint는 매 epoch 동일 외부 스마트폰 dev CER 최저값으로 선택하고 동률이면 EM, 이후 더 이른 epoch 순으로 결정한다. KORIE val과 필드 회귀 조건을 충족하지 못한 후보는 채택하지 않는다. test는 이 과정에 사용하지 않는다.

OOV·길이 초과는 학습 가능 여부와 사유를 남기고 외부 dev에서 조용히 제외하지 않는다. Box jitter는 글자를 잘라내면서 원래 문자열을 유지하는 라벨 오류를 만들지 않도록, 라벨 보존 검사가 구현된 후 별도 실험으로 추가한다.

## 5. 후보 승격·중단 기준

다음 기준은 이번 설계에서 정한 **개발 후보 선별 규칙**이다. 검증된 성능 목표나 제품 SLA가 아니다. 실행 전 policy 파일에 고정하고 결과를 보고 유리하게 완화하지 않는다.

1. 기준 재채점의 정수 집계·입력 ID가 모두 일치해야 한다. GPU 재실행 예측이 달라지면 캐시와 무조건 섞지 않고 새 기준 run으로 원인을 조사한다.
2. 개발 CER은 기준보다 낮고, EM·숫자/기호 EM은 기준 이상이어야 한다. 필드 GT가 있으면 금액·수량 EM도 기준 이상이어야 한다. 부족한 필드 GT는 ‘통과’ 대신 ‘미확인’으로 표시한다.
3. 새 인식기의 KORIE 전체 val CER은 2차 기준보다 나빠지지 않아야 한다. 이 규칙을 통과하지 못한 도메인 특화 모델은 자동 대체하지 않고 별도 후보로 보존한다.
4. 현재와 같은 장비·측정 범위에서 전체 OCR p95는 재측정한 기준의 1.10배 이내를 1차 비용 기준으로 제안한다. 이를 넘으면 자동 채택하지 않는다. 실제 서비스 SLA는 별도 요구사항으로 정의한다.
5. 영수증 단위 paired bootstrap 2,000회, seed 42로 CER 차이 구간을 보고한다. 0을 포함하면 탐색적 개선으로 분류한다. 다수 후보를 비교한 개발 구간으로 일반화·통계적 확증을 주장하지 않는다.
6. 오류·누락 샘플을 제외해 조건을 통과시키지 않는다. 입력 해시 변경·라벨 불일치·NaN·잘못된 checkpoint 로딩은 해당 단계 실패로 처리하고 이전 성공 결과는 유지한다.

독립 test는 동결 후보와 기존 기준을 같은 입력·정책으로 비교한다. 기준을 충족하지 못하면 기존 모델을 유지하고 실패도 보고한다. test 결과에 맞춰 다시 수정한 후보는 별도 신규 검증 자료가 필요하다.

## 6. 코드 구조 및 산출물 설계

확인된 재사용 대상은 [매칭 구현](../partial_matching_v1.py), [영역 실험 실행기](../region_improvement_20261118_v1/region_experiment.py), [영역 처리 모듈](../region_improvement_20261118_v1/receipt_regions_v1.py), [학습 진입점](../train_round2.py)이다. 기존 버전을 수정하지 않고 새 모듈에서 호출하거나 버전을 분리한다. 기존 2차 학습 guard를 그대로 스마트폰 학습에 사용할 수 있는지는 구현 시 확인한다.

새 구현 예정 위치는 `test_retro/implementation_v1/`, 실행 결과는 `test_retro/runs/<실험ID>_<시각>/`다.

| 새 모듈(예정) | 책임 | 핵심 입력 → 출력 |
|---|---|---|
| `run_experiment.py` | prepare/replay/smoke/evaluate/freeze/test 단계 제어 | policy + manifest → 단계 상태·실행 기록 |
| `region_variants.py` | 여백·분할·병합 변형과 좌표 추적 | 원본 이미지·공통 검출 캐시 → crop·부모 관계 |
| `score_layers.py` | 부분 GT·완전 GT·필드 지표 분리 | GT·예측 → 분자/분모·오류 분해·paired 비교 |
| `prepare_phone_rec.py` | 그룹 분할·학습 목록·보류 감사 | 검증 라벨·그룹 정보 → train/dev 목록·누수 검사 |
| `train_phone_rec.py` | 별도 학습·resume·export 및 선택 | 검증된 학습 가중치·목록 → checkpoint·선택 근거 |
| `benchmark_pipeline.py` | 단계별 GPU 시간·운영 시간 분리 | 동결 모델·입력 → 시간·메모리·실패 기록 |

각 run은 다음 파일을 남긴다.

- `manifest.json`: 데이터·라벨·모델·코드 SHA256, 상대 경로, split/group ID, seed, 패키지·컨테이너 정보.
- `policy.json`: 실제 유효 설정, 변경 변수, 정규화·매칭·ignore 규칙, 후보 선택 기준.
- `predictions.jsonl`: receipt/line/detection/crop ID, 원문 예측, 좌표, confidence, 부모 관계, 실패 사유.
- `metrics.json`: 평가 범위, 표본 수, GT 문자 수, 편집 수, EM 수, 미매칭·미채점 수, 필드별 결과.
- `paired_comparison.csv`: 기준/후보의 같은 GT별 변화, 매칭 변경, 정답→오답·오답→정답 구분.
- `timings.csv`, `failures.jsonl`, `status.json`, `decision.md`: 비용·실패·단계 상태·채택/보류 근거.

검출 캐시는 이미지 해시·검출기 해시·유효 검출 설정·전처리 버전으로 식별한다. 인식 캐시는 crop 해시·인식기 해시·인식 전처리 버전으로 식별한다. 여백 변경 시 기존 인식 결과를 재사용하지 않는다. 재채점만 바뀌면 원문 예측은 재사용할 수 있다.

새 run은 기존 폴더가 있으면 실패하도록 한다. resume은 manifest와 정책이 같은 run의 미완료 단계에만 허용한다. 평가 실패 재시도는 attempt별 새 폴더에 기록한다. freeze 이후 모델·정책·split 변경은 거부하고, test 진입은 freeze 증거와 신규 test 독립성 검사를 요구한다.

## 7. 구현 검증과 완료 체크리스트

| 검증 | 필수 사례 | 성공 기준 |
|---|---|---|
| 매칭·집계 | 예측 0개, GT 0개, 동일 IoU, 다중 후보, split/merge | 최대 대응 규칙과 분자·분모 정확, 0분모는 N/A |
| geometry | 회전·이미지 경계·인접 행·한 자리 숫자 | 좌표 유효, crop 출처 추적, 무조건 작은 박스 제거 없음 |
| ignore | 판독 가능 GT와 ignore 동시 겹침, ignore만 겹침 | 정의한 우선순위·면적 기준 재현 |
| 학습 입력 | 그룹 중복, OOV, 긴 문자열, 깨진 이미지 | 누수 거부·보류 사유 기록·외부 dev 보존 |
| 상태 제어 | 모델/라벨 변경 후 resume, freeze 후 변경, 중복 test | 잘못된 재사용 거부, 기존 성공 산출물 보존 |
| 실제 smoke | 고정 소량 이미지, 실제 export·재평가 | GPU 실행 완료·예측/실패 기록·기준 비교 가능 |

완료 산출물은 재현 가능한 코드·정책·run 기록, 부분/완전 GT를 구분한 평가표, 개발/독립 test를 구분한 결과, 채택 또는 유지 결정, 배포 후보 export 및 해시다. 준비되지 않은 완전 GT·신규 test·서비스 SLA는 미확인 항목으로 남기고 완료했다고 보고하지 않는다.
